# 513X-4S 15.9 V PID 网页复调

日期：2026-07-19

## 范围

- 双 MG513X、GMR AB 编码器、轮组架空。
- 用户提供母线表测值 15.9 V；板载电压分压链路未验收，未用于补偿。
- 真实 Google Chrome、本机持久串口桥、实体 `COM9 / 230400`。
- 每组轨迹固定为 `0 -> 30 -> 70 -> 30 -> 0 rpm`，最终命令必须收到 ACK。

## 排障

- 第一组右轮整只落下并碰到地面，负载条件发生变化，整组数据作废。
- 停机后网页出现约 `278/-70 rpm` 尖峰。原始帧证明固件在退出速度模式后把相同字段改为
  原始编码器 delta，网页仍按 rpm/PWM 解码；该尖峰不是实际速度。
- `SystemTask` 现在按最后控制模式保持字段语义，`ChassisActuator_ForceSafe` 不再把遥测模式
  强制改回电气点动。电气点动的原始编码器格式和活动标志仍保留。

## 启动助推

- 有效 `4/10/0` 基线中，600 permille 固定保持 100 ms，使 `0 -> 30 rpm` 峰值达到
  55.61/55.71 rpm，约 85.36%/85.71% 超调。
- 4S Profile 的 `boost_minimum_ms` 改为 20 ms；600 permille 起转幅值、双轮释放条件和
  500 ms 最大助推时间保持不变。低电压或带载时未达到释放速度会继续助推。
- 最终冷启动 `0 -> 30 rpm` 峰值 31.29/30.86 rpm，超调降至 4.29%/2.86%。
- 中间一次补丁曾命中相同布局的非活动 12 V Profile；A/B 无变化后立即定位并恢复。
  最终 12 V `MG513X v5` 仍保持 100 ms，只有 4S Profile 使用 20 ms。

## 用户 CSV 复盘与 v11 前馈重拟合

用户随后提供 `echo-pid-telemetry (1).csv`，共 10011 个 Control 样本，整段 PID 为
`5.5/8/0`。该文件确认两个剩余问题：

- 两次 `10 rpm` 左轮起步峰值为 20.04/21.86 rpm，尾段均值 9.85/9.73 rpm。
- 左轮保持 60 rpm 时右轮从 0 切到 60 rpm，右轮峰值 69 rpm，即 15% 超调。

v8 先修复运行中单轮从零切入没有独立启动状态的问题，并在助推退出后从实测速率开始
目标斜坡。右轮 `0 -> 60` 峰值降至 60.88 rpm；两次 `10 rpm` 峰值降至 13.07/12.64 rpm。

随后用 10/30/60/70 rpm 稳态总 PWM 重新拟合前馈，v9 使用左
`388.5 + 1.93*rpm`、右 `375 + 2.70*rpm`。完整轨迹结果：

- 两次 `10 rpm` 峰值均为 12.43 rpm，尾段均值 10.03/9.99 rpm。
- 左轮 `10 -> 60` t90 380 ms，峰值 62.25 rpm，尾段 59.91 rpm。
- 右轮 `0 -> 60` t90 260 ms，峰值 61.71 rpm，尾段 60.05 rpm。
- 70 rpm 尾段 70.02/70.08 rpm，积分仅 +1.95/-1.92 permille。

精确前馈使降速时输出下降更快，v9 的 `60 -> 30` 最低达到 25.50/26.14 rpm。
因此 v10 给目标斜坡增加独立降速参数：升速仍为 150 rpm/s，降速改为 90 rpm/s。
`Kp=5.5` 时最低改善为 26.57/27.00 rpm；RAM A/B 后最终选择 `Kp=6`：

| 轨迹 | t90 左/右 | 峰值或最低左/右 | 尾段左/右 |
| --- | ---: | ---: | ---: |
| 30->60 rpm | 320/190 ms | 61.82/62.16 rpm | 60.03/59.93 rpm |
| 60->30 rpm | 550/450 ms | 27.10/27.00 rpm | 29.99/30.30 rpm |
| 30->70 rpm | 300/250 ms | 71.46/72.00 rpm | 70.04/70.10 rpm |

`Kd=0.1` 只把左轮降速最低点提高到 27.85 rpm，右轮仍为 27.00 rpm，同时把左轮
`30 -> 60` t90 从 320 ms 拖慢到 380 ms，因此拒绝。最终 v11 固化 `6/8/0`。
