## 1. 定位与范围

- 串口无刷电机是云台主执行器。
- 第一代和第二代张大头闭环步进电机仅作为备用执行器，不属于当前主云台控制链。
- 两台电机均使用 Emm 固件和 TTL 串口直连。本实现不使用第二代资料中的 X 固件协议，
  也未实现 STEP/DIR 后端。
- 两代均已完成烧录、串口回包、位置/速度/停止/失能和速度租约实机验证；它们仍只作备用。

## 4. 软件边界

```text
未来云台执行器仲裁
  -> ZdtStepper_Request* / ZdtStepper_Service
    -> ZdtProtocol_Build* / Parse*
      -> BSP_ZdtUart_*
        -> UART2/UART3 + DMA_CH1/DMA_CH2
```

- `app` 只调用设备层，不拼协议字节，也不直接调用 DriverLib。
- `module/device/zdt_protocol.*` 负责 Emm 帧、响应解析和加速度单位换算。
- `module/device/zdt_stepper.*` 是两路备用电机的唯一命令状态机。
- `bsp/source/bsp_zdt_uart.c` 只负责 UART/DMA/RX ring，不判断云台模式。
- 当前尚未实现统一无刷/步进执行器仲裁；因此应用没有调用
  `ZdtStepper_SelectBackupBackend()`，张大头保持锁定。

## 5. 默认安全行为

- `ZdtStepper_Init()` 后 `backend_selected=0`。
- 未显式选择备用后端时，不查询、不使能、不接受速度/位置/停止请求，也不会自动运动。
- 相同速度或位置帧只发送一次，不随控制任务盲目重发；第一代相同速度请求会刷新 1.5 s
  安全租约但不重启电机内部加速轨迹，第二代未发送的旧运动目标会被最新目标覆盖。
- 第一代维持 20 ms 最小发送间隔、50 ms 轮询、20 ms 查询超时和连续 3 次超时离线。
- 第二代由 1 ms `ServiceTask` 驱动，最小发送间隔 2 ms；查询总频率约 100 Hz，按位置
  50 Hz、速度 25 Hz、状态 25 Hz 加权，查询超时 6 ms，连续 5 次超时离线。
- 高频位置轨迹可以抑制逐条详细回执，定期 Status 仍返回完整诊断，避免调试 UART 回执占满带宽。
- 从备用后端退出时，两路依次发送立即停止和失能，完成后才清除退出状态。
- 这些保证只覆盖 MCU 运行时逻辑。调试 halt、MCU 失电、线缆故障和电机内部参数错误仍需
  依靠物理断电、机构限位和后续故障验收。

## 6. 两代差异

| 行为 | 第一代 Emm | 第二代 Emm |
| --- | --- | --- |
| UART | 独立 UART2 | 独立 UART3 |
| 固件版本回复 | 5 B | 7 B |
| 相对当前坐标模式 | 不允许 | 允许 |
| 位置命令运行中更新 | 拒绝并返回 busy | 允许新目标排队发送 |
| 最小发送间隔 | 20 ms (50 Hz) | 2 ms (500 Hz 调度上限) |
| 稳态查询 | 每类约 6.7 Hz | 位置约 50 Hz、速度/状态约 25 Hz |
| 推荐位置用法 | 默认点到点；显式高频模式推荐 200 Hz | 200 Hz 连续目标跟踪 |
| 相同速度保活 | 主机可 200 Hz 保活，电机只在目标变化时收新帧 | 可按控制频率刷新电机速度帧 |

第一代位置目标未到达时禁止连续覆盖，是为了避免旧固件不断重规划、长期处于低速加速段。
第二代仍受相同目标去重约束；高频更新只保留尚未发送的最新目标，不积压过期轨迹。

## 7. 加速度与稳定命令策略

Emm 的原始 `acc` 是 8 位非线性编码，不是直接的 `RPM/s`。设备层对上层暴露物理
`acceleration_rpm_s`，按手册关系换算：

```text
acc = 0     -> 直接启动
acc = 10    -> 约 81 RPM/s
500 RPM/s   -> acc 0xD8
```

初次板测建议从 500 RPM/s 开始，再根据负载、电流、机械冲击和到速时间调整。稳定策略是
“目标变化时发送一次，由电机内部轨迹执行”，不是以控制循环频率反复发送同一位置帧。

## 8. 已验证与未验证

已验证：

- Emm 命令编码、响应解析和加速度换算 host 单元测试。
- mock UART 状态机：默认零发送、相同速度不重发、第一代位置忙拒绝、第二代位置更新、
  退出时两路停止并失能。
- SysConfig 生成 0 errors（保留 1 个既有 ProjectConfig warning）。
- FreeRTOS 与 App full rebuild 均为 0 Error / 0 Warning。
- 第二代地址 `0x01`、115200 8N1 实机在线，固件原始版本值 `200`，硬件原始版本值
  `8970 (0x230A)`。
- 第二代相对当前位置 `+15 deg` 后实测 `+15.007 deg`，反向返回后的基准误差为
  `0.044 deg`；正反速度反馈分别为 `+29/+30 rpm` 和 `-29/-30 rpm`。
- 显式停止后速度均回到 `0 rpm`；1.5 s 速度租约在不发送 Stop 时自动停止，过期计数增加 1。
- 最终第二代 `enabled=false`、`motion_active=false`、速度 `0 rpm`、状态位 `0x02`，
  无效响应、第二代超时、堵转和堵转保护计数均为 0。
- 单次位置控制两轮通过：`+15 deg` 实测约 `+15.0 deg`，回程基准误差小于 `0.05 deg`。
- 100 Hz、正弦 1 Hz、幅值 5 deg 的小角度跟踪 RMS 约 `0.83-0.99 deg`，最大误差约
  `1.29-1.52 deg`；由于 3200 pulse/rev 对应 `0.1125 deg` 目标量化，慢速峰值附近的重复帧
  会被去重，实际有效目标约 87 Hz。
- 三角 2 Hz、幅值 10 deg 的吞吐测试：请求 100/200/300/400 Hz，实发分别为
  `94.5/199.5/292.5/362.5 Hz`；全部无第二代超时、坏包或堵转，最终回中心误差不超过
  `0.055 deg`。
- 上述三角轨迹在 200 Hz 时 RMS 误差最低（约 `3.03 deg`）；400 Hz 虽通信稳定，但 RMS
  增至 `5.43 deg`、最大误差 `10.96 deg`。因此第二代推荐控制频率为 `200 Hz`，`400 Hz`
  只作为已验证的通信/调度上限，不作为云台默认值。
- 1 ms ServiceTask 烧录后静止 5 秒健康采集通过：Control/Health/Profile 为 100/1/1 Hz，
  CRC、gap、deadline、drop、UART overflow、I2C、active/sticky issue 全为 0。
- 第一代地址 `0x01`、115200 8N1 实机在线，固件版本值 `3`，硬件版本值 `130`；UART2
  使用 `PB15 TX -> 驱动 RX`、`PB16 RX <- 驱动 TX` 并共地。
- 第一代修复前，相同速度被去重但未刷新安全租约，200 Hz 主机保活下 20 秒只实发 27 个速度帧，
  发生 13 次租约过期，平均 `62.88 rpm`。修复后 200 Hz / 70 rpm / 20 秒发送 3995 个主机帧，
  平均 `67.62 rpm`，租约过期、超时、坏包和堵转均为 0。
- 第一代变化速度 `20 -> 40 -> 70 -> 40 -> 20 rpm`、200 Hz 保活、每段 4 秒通过；每段只在
  目标变化时向电机发 1 帧。稳态平均分别为 `20.09/40.56/66.28/40.81/19.42 rpm`，全程
  超时、坏包、租约过期和堵转均为 0。
- 第一代点到点位置 `+10 deg` 实测 `+9.965 deg`、约 `0.884 s` 到位；返回后净误差
  `0.264 deg`、约 `0.894 s` 到位，通信与堵转诊断全为 0。
- 第一代默认连续位置目标仍不作为云台跟踪接口：10 Hz 三角请求因“未到位时 busy”仅实发约
  `4.5 Hz`，RMS 误差约 `3.48 deg`。该限制用于避免旧固件反复重规划后长期慢转。
- 新增默认关闭的第一代高频位置覆盖模式。与二代相同的 `±10 deg / 2 Hz` 三角轨迹下，
  `10/20/30/50/75/100/150/200/300/400 Hz` 均无超时、坏包或堵转；400 Hz 请求实际
  `364.5 Hz`，说明通信/调度上限可到 400 Hz 档。
- 第一代高频位置的最佳有效频率为 `200 Hz`：`acc=0` 时 2 秒 RMS `6.065 deg`，10 秒耐久
  实发 `199.5 Hz`、1995 个位置帧、RMS `6.586 deg`、回中心误差 `0.033 deg`，全程通信和
  保护诊断为 0。300/400 Hz 跟踪变差，因此不推荐。
- 同一轨迹下第二代 200 Hz RMS 约 `3.033 deg`，约为第一代误差的一半；第二代仍是两台
  张大头中更适合连续位置云台的选择，无刷电机仍为主选。

未验证：

- 两代断线恢复、带载电流、温升、堵转保护和机械限位。
- 第一代反向速度阶梯和不同机械负载下的速度误差；高频位置模式下的电流、温升和机构冲击。
- 与未来无刷主后端的互斥切换和故障降级。

## 9. 实机验收门禁

开始运动测试前必须同时满足：

1. 用户人在现场并明确许可本次运动。
2. 机构架空或与负载脱开，默认目标为零，物理断电随手可用。
3. 分别确认两台电机的 TTL 电平、共地、TX/RX、地址、115200 8N1 和 Emm 固件。
4. 先只接一台，验证查询回包；再执行低速、小角度、单次目标。
5. 由用户给出云台安全速度、角度范围和初始加速度，未确认前不做连续或大角度运动。
6. 记录 TX/RX、响应超时、实际速度、到达状态、电流和温升；第一代重点复核不会长期慢转。

只有以上板测完成，才能把状态从“软件验证通过”提升为“备用执行器实机可用”。
